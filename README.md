# SpeedRim

A **RimWorld 1.6** mod that adds **5x**, **10x** and **20x** game speeds on top of the vanilla
time controls (pause / 1x / 2x / 3x).

📖 **Leia em português: [README.pt-BR.md](README.pt-BR.md)**

![Preview](About/Preview.png)

## Features

- **Three extra buttons** next to the vanilla time controls, in the bottom right corner.
- **Hotkeys**: `5`, `6` and `7` by default, rebindable in *Options -> Keyboard configuration*.
- The vanilla **speed up / slow down** keys keep working and now climb all the way to 20x.
- **Mod settings** (*Options -> Mod settings -> SpeedRim*):
  - the multiplier behind each button, anywhere from 2x to 100x;
  - show or hide the button row;
  - move the row horizontally and vertically, for when another mod uses the same corner;
  - whether the extra speeds obey the moments when the game forces normal speed (a raid arriving, for example);
  - whether the speed up / slow down keys are extended.

## How fast it really goes

The multipliers are **targets**, not promises. RimWorld runs as many ticks as fit in a frame and
stops as soon as it would fall below its minimum framerate, so a large colony or a slower CPU simply
runs below the number on the button — the game gets slower than the target instead of freezing.

## Installation

1. Install [Harmony](https://steamcommunity.com/sharedfiles/filedetails/?id=2009463077) (required dependency).
2. Copy this repository's folder into RimWorld's `Mods` folder, so that it looks like this:

   ```
   RimWorld/Mods/SpeedRim/About/About.xml
   RimWorld/Mods/SpeedRim/1.6/Assemblies/SpeedRim.dll
   ```

3. Enable **SpeedRim** in the mod list, after Harmony.

`SpeedRim.dll` is committed to the repository already built, so nothing has to be compiled to play.

## Building from source

Requires the [.NET SDK](https://dotnet.microsoft.com/download) (8.0 or newer). The RimWorld 1.6
references come from the `Krafs.Rimworld.Ref` NuGet package, so the game does not need to be
installed to build — and it works on Windows, Linux and macOS:

```bash
cd Source/SpeedRim
dotnet build -c Release
```

The result is written straight to `1.6/Assemblies/SpeedRim.dll`.

The button textures and the preview image are generated by a script (requires `pillow`):

```bash
python3 Source/Tools/generate_textures.py
```

## How it works

RimWorld's `TimeSpeed` runs from `Paused` (0) to `Ultrafast` (4). The mod uses values 5, 6 and 7 of
that same enum for the new speeds and answers for them in three Harmony patches:

| Patch | Target | Role |
| --- | --- | --- |
| `TickManager_TickRateMultiplier_Patch` | `TickManager.TickRateMultiplier` | Returns the configured multiplier for the new speeds; vanilla speeds fall through untouched. Honours pause, forced normal speed and vanilla's faster world-map-only tick rate. |
| `TimeControls_DoTimeControlsGUI_Patch` | `TimeControls.DoTimeControlsGUI` | Draws the three buttons to the left of the vanilla row and handles the hotkeys (the prefix runs before the game consumes the key events). |
| `TickManager_ExposeData_Patch` | `TickManager.ExposeData` | Writes a vanilla speed into the save file and puts the extra speed straight back afterwards. |

Keeping the active speed in the game's own `curTimeSpeed` means pausing/unpausing, saving/loading
and other mods that change the speed keep working without a parallel state machine. The `ExposeData`
patch is what keeps saves compatible with a game without the mod: a save made at 20x loads at
Superfast if SpeedRim is removed, instead of carrying an unknown value.

## Compatibility

- Can be added to and removed from ongoing saves.
- No vanilla method is replaced wholesale: the patches are prefixes and postfixes that leave the
  original path intact for the vanilla speeds.
- Works alongside other mods that touch the game speed, as long as they do not replace
  `TickRateMultiplier` entirely.
